Where the data lives

Branch new-idea, as built on 2026-10-12. Four places hold data; only one survives a restart.

Durable: SQLite

src/server/migrate.ts, db.ts, stock.ts
survives restart
  • visitors: identity, token, who they chose to be, look
  • player_state: one row per visitor (where they are in their visit)
  • conversations: script, current node, answers so far
  • stock and reservations: finite units, holds with a stored deadline
  • events: append-only, written first for every state change

Live only: server memory

src/server/presence.ts
lost on restart
  • sockets and positions (about 10 Hz, never persisted, never events)
  • the pending staff replies are rebuilt from conversations rows
  • nothing here may be needed for correctness after a restart

Computed: the clock

src/shared/storeday.ts, engage.ts
no storage
  • NPC timetable is a pure function of server time and fixed seeds
  • Fly auto-stops the machine, so there is no tick and no timer
  • Deadlines are columns caught up on the next request

Browser

src/client/src/net.ts
per viewer only
  • token and last profile in localStorage (blocked storage just means a new identity)
  • everything else is rebuilt from the welcome message

Code as data

src/shared/*.json, catalogue.ts
in the repo
  • layout.json: table, bench, stool positions (floor-plan editor writes it)
  • catalogue.ts: the placeholder phones (placeholders) and START_STOCK, seeded into the stock table at boot
  • conversation.ts: the scripts
